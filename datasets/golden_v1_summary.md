# RAGAS 종합 결과: golden_v1

## 발표용 결과 요약

### 진행 흐름

| 단계 | 한 일 | 결과 |
| --- | --- | --- |
| 1. 데이터셋 생성 | 정책 150건을 고정 시드로 뽑아 `TestsetGenerator`로 질문·정답 후보 생성 | 후보 129건 |
| 2. 검수 | 후보 전수를 정책 원문과 대조해 모호·동명 정책·정답 오류 등 29건 제외 | `golden_v1` 100건 |
| 3. baseline 측정 | 검색 없이 LLM(gpt-6-luna)에 질문만 전달 | 문서 없는 LLM의 기준 점수 |
| 4. rag 측정 | 로컬 RAG 서버(정책 통째 임베딩, top_k 10)에 같은 질문 전달 | RAG 점수, 검색 적중률 |

비용 때문에 baseline과 rag 모두 1회만 실행했다.

### baseline vs rag

| 지표 | 비교 대상 | baseline | rag | 차이 |
| --- | --- | --- | --- | --- |
| factual_correctness | 정답 ↔ 답변 | 0.101 | **0.446** | +0.345 |
| reference_faithfulness | 정책 원문 ↔ 답변 | 0.204 | **0.601** | +0.397 |
| answer_relevancy | 질문 ↔ 답변 | 0.662 | 0.615 | -0.047 |
| faithfulness | 검색 결과 ↔ 답변 | - | 0.858 | |
| context_recall | 정답 ↔ 검색 결과 | - | 0.894 | |
| context_precision | 질문·정답 ↔ 검색 결과 순위 | - | 0.754 | |

### 검색 적중률 (정답 정책이 검색 결과 10건 안에 있는지)

| 지표 | 값 | 의미 |
| --- | --- | --- |
| Hit@1 | 54% | 정답 정책이 1위로 검색됨 |
| Hit@3 | 74% | 3위 안 |
| Hit@10 | 85% | 10위 안 (top_k 전체) |
| MRR | 0.654 | 정답 정책 순위의 역수 평균 |

Hit@k와 MRR은 rag 샘플의 검색 결과(`metadata.retrieved_chunks`)로 따로 계산한 값이다. DB 지표 컬럼에는 없다.

### 검색 적중률은 어떻게 구했나

RAG는 질문마다 검색 결과 10건을 돌려준다. 그 안에 **정답 근거 정책이 있는지, 몇 위인지를 코드로 판정**했다. LLM은 쓰지 않는다.

| 단계 | 내용 |
| --- | --- |
| 1. 정답 근거 | 데이터셋 샘플의 `policy_no` (질문을 만든 정책 1개) |
| 2. 검색 결과 | RAG가 돌려준 10건, 건마다 `policy_no`와 점수 |
| 3. 순위 찾기 | 점수 순으로 보며 정답 `policy_no`와 같은 건이 처음 나오는 순위. 10건 안에 없으면 못 찾음 |
| 4. 샘플별 값 | Hit@k: 순위가 k 이내면 1, 아니면 0 / MRR: 1 ÷ 순위 (1위 1, 2위 0.5, 3위 0.33, 못 찾으면 0) |
| 5. 집계 | 100건 평균 |

| 예 | Hit@1 | Hit@3 | Hit@10 | MRR |
| --- | --- | --- | --- | --- |
| 정답 정책이 1위 | 1 | 1 | 1 | 1 |
| 정답 정책이 2위 | 0 | 1 | 1 | 0.5 |
| 10건 안에 없음 | 0 | 0 | 0 | 0 |

계산 전제는 모두 확인했다.
- 검색 결과는 100건 모두 점수 내림차순으로 저장되어 있다.
- 로컬 `policy_chunk`는 정책 하나를 1건으로 넣어서 같은 정책이 겹친 검색 결과가 없다. 그래서 청크 순위가 곧 정책 순위다.
- golden_v1은 정책 하나로 만든 질문이라 질문마다 정답 정책이 1개다.

**ragas 근거 지표와의 차이**

| 구분 | Hit@k, MRR | context_recall, context_precision |
| --- | --- | --- |
| 판정 주체 | 코드 (정책 ID 비교) | 채점 LLM |
| 보는 것 | 정답 정책을 검색했는가 | 정답 내용이 검색 결과 본문에 들어 있는가 |
| 장점 | 명확하고 매번 같은 결과, 비용 없음 | 다른 정책에 같은 내용이 있어도 인정 |
| 단점 | 내용이 같은 다른 정책(동명 정책 등)을 가져오면 틀린 것으로 셈 | LLM 판단이라 흔들리고 비용이 듦 |

Hit@10(85%)보다 context_recall(0.894)이 조금 높은 것은, 정답 정책은 못 찾았지만 비슷한 내용의 다른 정책을 가져와 내용상으로는 인정된 경우가 있기 때문이다.

### 의미

| 관찰 | 해석 |
| --- | --- |
| 사실 정확도 0.10 → 0.45 (4.4배) | 정책 문서를 찾아 근거로 쓰면서 할루시네이션이 크게 줄었다. 100건 중 83건에서 rag가 baseline보다 높고, 낮은 건 8건 |
| 원문 근거 0.20 → 0.60 | 답변 내용의 60%가 실제 정책 원문으로 뒷받침된다 |
| 검색 결과 충실도 0.86 | 검색해 온 문서 안에서는 대체로 지어내지 않고 답한다 |
| 검색이 핵심 | 정답 정책을 검색한 85건은 사실 정확도 0.479, 놓친 15건은 0.258 |
| 관련성은 비슷 (0.66 → 0.62) | 두 모드 모두 질문 주제에 맞춰 답한다. rag는 "다만 …" 같은 조건·안내 문장이 붙어 조금 낮다 |

**결론**: RAG를 붙이면 정책 사실 정확도와 원문 근거가 크게 오른다. 남은 개선 여지는 검색(정답 정책 1위 비율 54%)에 있다.

### 점수가 낮은 원인

| 원인 | 설명 | 예시 |
| --- | --- | --- |
| 1. 검색 실패 | 정답 정책이 검색 결과 10건에 없음 (15건). 같은 종류 정책이 여러 지역에 있으면 다른 지역 정책을 가져온다 | 058: "지역주도형 청년일자리사업" 질문에 다른 시군 사업을 답함 (context_recall 0.3) |
| 2. 엄격한 채점 | factual_correctness는 사실 단위 F1이라, 답이 맞아 보여도 정답과 사실 쪼개는 방식이 다르면 0점이 나온다 | 102: "면접 1회당 5만원 지역화폐, 연 최대 3회"로 정답과 같은데 0점. 092도 같은 경우 |
| 3. 정답에 없는 안내 | RAG가 신청 상태("마감됐어요", "신청 상태: 정보 없음")나 다른 공고 내용을 덧붙이면 정답에 없는 사실로 처리된다 | 044, 058 |
| 4. 지역 정보 없음 | 지역 없이 같은 이름 정책을 물으면 다른 지역 정책이 검색된다 (피드백 1번) | 해당 7건: Hit@10 4건, 사실 정확도 0.356 (나머지 0.453) |

### 피드백 항목별 rag 점수

| 피드백 그룹 | 건수 | rag factual_correctness | 나머지 | Hit@10 |
| --- | --- | --- | --- | --- |
| 1. 지역 정보 없음 | 7 | 0.356 | 0.453 | 4/7 |
| 2. 질문자 설정 불일치 | 9 | 0.616 | 0.429 | 7/9 |
| 3. 마감 정책 | 48 | 0.429 | 0.462 | 42/48 |

- 지역 정보가 없는 질문은 검색을 자주 놓쳐 점수가 낮다. 생성 코드에 지역 줄을 추가한 이유다.
- 마감 정책은 점수 차이가 작다. 정답과 근거에 마감 여부가 없어 RAG의 마감 안내가 크게 감점되지는 않았다.
- 질문자 설정 불일치 9건은 오히려 높다. 정답이 대상 여부를 말하지 않아도 사실 부분은 맞힌 경우가 많다.
